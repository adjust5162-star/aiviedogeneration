# 아키텍처

## 흐름

1. 브리프: 주제, 플랫폼, 비율, 길이, 참고 에셋과 권리를 입력합니다.
2. 스토리보드: 공급자 한도에 맞는 짧은 장면으로 분할합니다.
3. 프롬프트 디렉터: 한국어 미리보기, 영문 프롬프트, JSON, 부정 제약을 만듭니다.
4. 생성 또는 가져오기: 수동, Gemini, 로컬 모드 중 하나를 사용합니다.
5. 품질 검토: 해상도·프레임·오디오 같은 기술 기준과 사람이 판단할 시각 기준을 분리합니다.
6. 후반 작업과 내보내기: 원본을 덮어쓰지 않고 파생 파일을 만듭니다.

`app/api`의 서버 경계가 비밀키와 유료 호출을 담당합니다. 브라우저에는 API 키를 전달하지 않습니다. 현재 배포판은 사용자 파일을 영구 업로드하지 않는 안전한 데모이며, 실제 미디어 영구 저장은 R2와 메타데이터 DB를 추가해야 합니다.

## 제공자 구조

- Manual: 공식 소비자 UI에서 직접 생성하고 권리 있는 파일만 가져옵니다.
- Gemini Omni: Interactions API의 `gemini-omni-flash-preview`.
- Veo: 고급 프레임·확장·레퍼런스가 필요할 때 `veo-3.1-*` 계열.
- Mock: 테스트와 UI 검증에서 비용 없이 결정적으로 완료됩니다.

유료 모델의 자동 폴백과 자동 재시도는 금지합니다.
